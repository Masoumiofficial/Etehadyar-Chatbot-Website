# وب‌سایت اتحادیار — سورس قابل نگهداری و CMS امن

این مخزن **سایت معرفی محصول** اتحادیار را نگهداری می‌کند؛ خود افزونه/پوسته وردپرس، مدل AI، درگاه پرداخت یا صف وردپرس داخل این بسته نیست. شماره `6.12.0` شماره محصول معرفی‌شده است، نه ادعای انتشار نسخه جدید افزونه.

نام قبلی `ehehadyar-chat-theme.zip` برای سازگاری با مخزن حفظ شده است. ZIP را در روت هاست استخراج کنید؛ آن را به‌عنوان افزونه یا پوسته وردپرس نصب نکنید.

## چه چیزهایی اصلاح شده‌اند؟

- احراز هویت سرور با نشست، کوکی HttpOnly/SameSite، توکن CSRF، محدودسازی پایدار ورود و انقضای نشست.
- حذف حساب پیش‌فرض و رمز مرورگر؛ نگهداری فقط **هش رمز** خارج از روت عمومی.
- ذخیره اتمی JSON، اعتبارسنجی متن/نسخه/قیمت/URL و جلوگیری از بازنویسی تغییرات نشست دیگر.
- خواندن تیتر، توضیحات، FAQ، قیمت و تاریخچه از داده مشترک در صفحات عمومی؛ رندر متنی برای جلوگیری از XSS ذخیره‌شده.
- اعلان صحیح خطا؛ شکست ذخیره یا وارد کردن پشتیبان به معنی انتشار نیست.
- خروجی ZIP واقعی پشت احراز هویت، بدون رمز، نشست، لاگ ورود یا اطلاعات خصوصی.
- اصلاح چیدمان موبایل، منوی صفحات فرعی، عنوان اختصاصی صفحات، برچسب اسلایدرها، کنتراست و کنترل فوکوس مودال‌ها.
- خرید فقط با لینک HTTPS واقعی هر ارز فعال می‌شود؛ لینک خالی به صفحه اصلی برنمی‌گردد.
- شفاف‌سازی دموها: صوت‌های آماده MP3 هستند و شاخص‌های نمایشی، سلامت واقعی AI یا هاست را گزارش نمی‌کنند.

## تم روشن، ظاهر سینمایی و کنترل حرکت

- تم پیش‌فرض تمام صفحات عمومی و پنل **روشن** است. دکمهٔ ماه/خورشید در سربرگ، تم تیره را هم در اختیار شما می‌گذارد.
- دکمهٔ لایه‌ها، جلوهٔ عمق را روشن/خاموش می‌کند. انتخاب ظاهر در localStorage ذخیره می‌شود؛ هیچ دادهٔ ورود یا پیش‌نویسی در آن نگهداری نمی‌شود. اگر storage مسدود باشد، خود کنترل‌ها همچنان کار می‌کنند.
- ظاهر جدید صفحات عمومی سینمایی است؛ صفحه اصلی و تاریخچه صحنهٔ سه‌بعدی CSS با مکعب شش‌وجهی، مدارها، نور و کارت‌های شناور دارند. «۵بعدی» در درخواست قبلی صرفاً برداشت بصری از عمق بود، نه فناوری پنج‌بعدی واقعی.
- حرکت فقط در دستگاه دارای ماوس/قلم مناسب و عرض بیشتر از ۹۰۰ پیکسل اجرا می‌شود؛ روی موبایل، حالت کاهش حرکت، حالت کنتراست اجباری و تب پنهان خاموش است. متن و دکمه‌ها نمی‌چرخند و هیچ کتابخانه سه‌بعدی، canvas یا حلقهٔ دائمی رندر اضافه نشده است.
- تنظیمات تم در `assets/css/appearance.css` و `assets/js/appearance.js`، و صحنه/رفتار سینمایی در `assets/css/cinematic.css` و `assets/js/cinematic.js` هستند. تصویرهای پنل محصول، همان دارایی‌های اصلی‌اند و تغییر رنگ عکس‌ها به معنی تغییر خود محصول نیست.
- منوی سایت و جست‌وجوی تاریخچه منتظر دریافت CMS نمی‌مانند؛ نسخه استاتیک و کنترل‌ها هنگام کندی داده در دسترس‌اند. خرید تا دریافت دادهٔ معتبر و مقصد واقعی همچنان بسته می‌ماند.

### اسکرول و تاریخچهٔ جدید

- اسکرول نرم دسکتاپ از **Lenis 1.3.26** با مجوز MIT استفاده می‌کند؛ فایل minified و مجوز در `assets/js/vendor/` نگهداری می‌شوند. CDN یا درخواست ثالثی لازم نیست و نسخه با dependency پین‌شده تطبیق داده می‌شود.
- اسکرول نرم فقط با حرکت مجاز و دستگاه مناسب فعال است. موبایل، reduced motion، forced colors، خاموش‌کردن جلوه‌ها یا نبود فایل اختیاری vendor، اسکرول native دارند. RAF اسکرول فقط حین انیمیشن فعال است و پس از سکون قطع می‌شود؛ حرکت‌های CSS صحنه نیز فقط در viewport و حالت مجاز اجرا می‌شوند.
- Ctrl/Shift+wheel، اسکرول داخلی جدول/منو/فهرست، لمس و کیبورد به رفتار مناسب مرورگر واگذار می‌شوند. هنگام لایت‌باکس یا منو، اسکرول پس‌زمینه قفل و با بستن آن آزاد می‌شود.
- تاریخچه قالب روشن لایه‌دار، جست‌وجو/فیلتر، دسترسی مستقیم به نسل‌ها، نوار ابزار چسبان دسکتاپ، فهرست نسل‌ها و درصد واقعی اسکرول صفحه دارد. درصد مطالعه، نتیجه AI یا آمار سلامت نیست.
- لینک‌های کیبورد مقصد را زیر سربرگ/نوار جست‌وجو قرار می‌دهند و فوکوس را به عنوان مقصد می‌برند. کلید بازگشت به بالا نیز فوکوس را به h1 بازمی‌گرداند.
- پنل CMS عمداً جلوهٔ سینمایی و Lenis ندارد تا ویرایش متن/فرم پایدار و آرام بماند.

## اجرای محلی و پیش‌نمایش

Node فقط برای توسعه و تست لازم است؛ سایت منتشرشده به npm، Build یا CDN نیاز ندارد.

```sh
npm ci --ignore-scripts
npm run dev
```

سرور توسعه روی `0.0.0.0:8080` اجرا می‌شود و PHP 8.3 را با WebAssembly اجرا می‌کند. همه درخواست‌های مرورگر به URL نسبی همان سایت می‌روند؛ روی دامنه پیش‌نمایش نیز کار می‌کند. اطلاعات خصوصی پیش‌نمایش به‌صورت پیش‌فرض در پوشه هم‌سطح و خارج از مخزن نگهداری می‌شود. تا وقتی مدیر ایجاد نشده باشد، پنل ورود عمداً غیرفعال است. ایجاد حساب در پیش‌نمایش، حساب هاست را ایجاد نمی‌کند؛ اطلاعات مدیر همچنان خارج از مخزن می‌مانند و ZIP عمومی شامل آن‌ها نیست.

محدودسازی فایل‌های خصوصی و سربرگ‌های امنیتی در این سرور توسعه اعمال می‌شوند. برای تولید، وب‌سرور واقعی PHP و تنظیمات زیر را استفاده کنید، نه سرور توسعه Node.

## انتشار روی هاست

### ۱. فایل‌های عمومی و PHP

1. با `npm run build:release` بسته را بسازید یا از ZIP به‌روزشده مخزن استفاده کنید.
2. فایل‌های ZIP، از جمله `.htaccess`های مخفی، را در روت عمومی (مثلاً `public_html`) استخراج کنید.
3. برای CMS، **PHP پشتیبانی‌شده 8.3 یا بالاتر** را به کار ببرید. کد از نگارش 7.4 استفاده می‌کند، اما نسخه‌های پایان‌عمر PHP انتخاب امنی برای تولید نیستند.
4. HTTPS را فعال کنید. روی Apache 2.4، دستورات `Require` و تنظیمات `.htaccess` باید مجاز باشند؛ `mod_rewrite` و `mod_headers` را فعال کنید. برای Nginx، `.htaccess` خوانده نمی‌شود؛ نمونه `deploy/nginx.conf.example` را با دامنه، مسیر و سوکت PHP واقعی خود تطبیق دهید.
5. دسترسی HTTP به `scripts/`، `tests/`، `.git/`، فایل‌های پیکربندی توسعه، ZIPهای روی دیسک و `data/admin_creds.json` قدیمی را ببندید. فهرست‌کردن پوشه‌ها نباید فعال باشد.
6. پوشه `data/` باید برای کاربر PHP قابل نوشتن باشد تا جایگزینی اتمی فایل انجام شود. از `chmod 777` استفاده نکنید؛ مالکیت صحیح برای کاربر PHP را تنظیم کنید.

### ۲. فضای خصوصی و ایجاد مدیر

اطلاعات مدیر و نشست‌ها **نباید داخل روت وب** باشند. یک مسیر مطلق خارج از `DOCUMENT_ROOT` انتخاب کنید و آن را در محیط PHP تنظیم کنید:

```text
ETEHADYAR_PRIVATE_DIR=/home/ACCOUNT/.etehadyar-private
```

این مسیر نمونه است؛ `ACCOUNT` را با مسیر واقعی هاست جایگزین کنید. پوشه خصوصی با مجوز `0700` و فایل‌های حساس با `0600` ساخته می‌شوند. کاربر اجرای PHP باید مالک/دارای دسترسی به آن باشد. فایل خصوصی را در Git یا ZIP سایت قرار ندهید.

**با دسترسی ترمینال:** در روت سایت و با همان کاربری که PHP اجرا می‌شود:

```sh
php scripts/setup-admin.php --username YOUR_USERNAME --private-dir=/home/ACCOUNT/.etehadyar-private
```

رمز انتخابی را در ترمینال وارد و تأیید کنید؛ حداقل ۱۲ کاراکتر و حداکثر ۷۲ بایت UTF-8. رمز در آرگومان فرمان یا خروجی چاپ نمی‌شود و فقط هش آن ذخیره می‌شود. هیچ رمز پیش‌فرضی وجود ندارد. تنظیم مسیر در CLI و محیط PHP باید یکسان باشد، به‌خصوص اگر سایت در زیردایرکتوری نصب شده است.

**بدون ترمینال هاست:** مدیر هاست می‌تواند `ETEHADYAR_ADMIN_USERNAME` و `ETEHADYAR_ADMIN_PASSWORD_HASH` را در محیط خصوصی PHP تنظیم کند. مقدار دوم باید هش معتبر `password_hash` باشد، نه رمز خام. اولین درخواست آن را به فایل خصوصی منتقل می‌کند؛ پس از آن فایل خصوصی مرجع است و می‌توان این متغیرهای راه‌اندازی را حذف کرد. اطلاعات ورود را در چت، سورس عمومی، `config.js` یا یک `.env` عمومی قرار ندهید.

برای بازیابی عمدی حساب موجود:

```sh
php scripts/setup-admin.php --username YOUR_USERNAME --private-dir=/home/ACCOUNT/.etehadyar-private --reset
```

تأیید رمز فعلی نیز محدودسازی پنج شکست در ۱۵ دقیقه دارد؛ این محدودیت با ورود، در سطح IP مشترک است. رمز اشتباه `403` است، نه اعلام اشتباه انقضای نشست.

اجرای دستور `--reset` نشست‌های قبلی را باطل می‌کند. تغییر رمز عادی از پنل نیازمند رمز فعلی است و فقط نشست جاری را معتبر نگه می‌دارد.

اگر پشت یک **پروکسی قابل اعتماد** هستید و TLS آنجا خاتمه می‌یابد، فقط وقتی آن پروکسی سربرگ‌های ورودی کاربران را پاک‌سازی می‌کند `ETEHADYAR_TRUST_PROXY=1` تنظیم کنید. در حالت عادی آن را فعال نکنید. TLS مستقیم با `HTTPS=on` به‌طور خودکار کوکی Secure دارد.

### ۳. راه‌اندازی لینک خرید

از `/admin/` وارد شوید و در «تنظیمات و قیمت‌گذاری»، لینک‌های واقعی HTTPS پرداخت ایران و بین‌الملل را جداگانه ثبت کنید. لینک صفحه اصلی محصول، `javascript:`، HTTP و URL حاوی نام کاربری/رمز پذیرفته نمی‌شوند. تا پیش از این تنظیم، خرید و پیشنهاد خرید در اسکیما غیرفعال‌اند؛ هیچ درگاه فرضی در کد قرار نگرفته است.

### ۴. ارتقا از نسخه ناامن قبلی

- پوشه `admin/` و اسکریپت‌ها/استایل‌های جدید را **کامل** جایگزین کنید؛ فقط تغییر UI کافی نیست.
- رمز پیش‌فرض قبلی را دوباره استفاده نکنید. اگر قبلاً `data/admin_creds.json` ساخته شده، پس از راه‌اندازی امن آن فایل عمومی و هر نسخه پشتیبان عمومی‌اش را حذف کنید.
- محتوای ذخیره‌شده قبلی را جداگانه پشتیبان بگیرید. داده عمومی مرکزی این نسخه را با نسخه قدیمی که لینک خرید به صفحه اصلی دارد بی‌بررسی جایگزین نکنید.
- کش CDN/مرورگر را پاک کنید. فایل JSON، HTML و JS باید با بازاعتبارسنجی دریافت شوند.
- تا کامل‌شدن ارتقا و ایجاد مدیر، دسترسی عمومی API قدیمی را محدود نگه دارید.

## مدیریت محتوا و پشتیبان

- منبع اصلی محتوای قابل ویرایش: `data/site_data.json`. این فایل **عمومی** است؛ هیچ کلید API، رمز یا اطلاعات شخصی در آن ذخیره نکنید.
- `assets/js/config.js` فقط fallback ایمن است، نه فایل تولیدشده هنگام ذخیره.
- «ذخیره و انتشار» نیازمند پاسخ موفق سرور است. بازگردانی JSON فقط پیش‌نویس را تغییر می‌دهد و هنوز باید ذخیره کنید.
- اگر نشست هنگام ویرایش منقضی شود، پیش‌نویس **فقط در حافظه همین تب** نگه داشته می‌شود. توکن ورود تازه می‌شود و پس از ورود، پیش‌نویس بدون انتشار خودکار بازمی‌گردد؛ حتی در خطای خواندن داده می‌توانید JSON آن را صادر کنید. تازه‌کردن یا بستن تب این حافظه را پاک می‌کند؛ برای نگهداری حتماً خروجی بگیرید. خروج عمدی، پیش‌نویس را پاک می‌کند.
- پاسخ `409` یعنی نشست دیگری داده را عوض کرده؛ ابتدا پیش‌نویس خود را صادر کنید و سپس داده سرور را دوباره بارگذاری کنید. ذخیره کورکورانه آخرین تغییرات کاربر دیگر را حذف نمی‌کند.
- ویرایشگر نسخه‌ها فهرست متنی تغییرها را ویرایش می‌کند. اگر فقط عنوان/شماره نسخه را عوض کنید، زیرعنوان‌های موجود حفظ می‌شوند؛ تغییر فهرست، آن نسخه را به فهرست تخت تبدیل می‌کند. برای ساختار بخش‌بندی‌شده، از JSON واردشده با `subsections` منطبق با `items` استفاده کنید.
- ZIP پنل، آخرین **داده‌های ذخیره‌شده** و فایل‌های عمومی را شامل می‌شود؛ نه ویرایش‌های منتشرنشده و نه اطلاعات ورود مدیر. پس از استقرار آن روی هاست جدید، مدیر باید دوباره راه‌اندازی شود.
- صفحات عمومی برای اعمال ویرایش‌های JSON به JavaScript نیاز دارند. در شکست بارگذاری داده، محتوای استاتیک اولیه نمایش داده می‌شود، هشدار دیده می‌شود و خرید بسته می‌ماند.
- زبان انگلیسی برای معرفی، قیمت‌گذاری و FAQ در دسترس است؛ بخش‌های فنی و مستندات فعلاً فارسی‌اند و این محدودیت در UI اعلام شده است.

## آزمون‌ها و ساخت بسته

```sh
npm test                 # امنیت API، انتشار، اعتبارسنجی، لینک‌ها و بسته تکرارپذیر
npm run test:browser     # تست مرورگر، CMS واقعی، موبایل، فوکوس و axe
npm run build:release    # بازسازی ehehadyar-chat-theme.zip فقط از فایل‌های مجاز
```

تست‌ها روی کپی موقت سایت با حساب تصادفی اجرا و سپس پاک می‌شوند؛ به داده‌های واقعی پروژه یا هاست دست نمی‌زنند. وابستگی‌های توسعه و مرورگر در `node_modules` هستند و در Git/ZIP قرار نمی‌گیرند. ZIP توسعه با Python استاندارد و ZIP پنل با PHP بدون نیاز به ZipArchive ساخته می‌شود.

گزارش بررسی و محدودیت‌ها: `AUDIT-FULL-REPORT.md`. تست خودکار، تضمین امنیت کامل یا گواهی WCAG نیست. دامنه زنده، SSL، DNS، درگاه پرداخت، تنظیمات وب‌سرور هاست و عملکرد خود افزونه باید در محیط واقعی جداگانه تأیید شوند.
